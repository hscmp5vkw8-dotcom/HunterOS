# HunterOS account and data deletion

Operator procedure, September 26, 2026. This document is not an automated deletion service. No real user records were deleted while preparing it.

Public requests: https://hunteros-support.j5fyt5h7qj.chatgpt.site/delete-account/
Inbox: support@gethunteros.com. Monitor this inbox during the beta. Aim to complete verified requests within 30 days; acknowledge requests and explain verification or any narrow legal hold. Do not request passwords or sign-in codes.

1. Verify ownership through the account email and a fresh confirmation reply. For a lost email, establish another reliable ownership method before acting; knowing an email or a display name alone is insufficient. Record only the account email, request date, verified account UUID, requested scope and status in private support records. Do not put personal data in source control.
2. Confirm whether the request is full account deletion or selected-data deletion. Explain that full deletion is permanent, removes groups the person owns and their associated posts, and does not erase device workspaces, exported files or recipients' copies. Do not export their workspace into support records. Handle any specific legal/security exception narrowly and explain it where permitted.
3. Inspect the exact account UUID and row counts in the current database before deletion. Verify the deployed foreign keys; do not rely solely on this document if the schema has changed. Delete associated `feedback_reports` explicitly BEFORE deleting the auth user: `reporter_user_id` is SET NULL on auth deletion, and the `report` JSON may contain email or other identifying text. Match unsigned feedback only using verified email/report references, and avoid deleting another person's report. Review operator notes, support copies and attached reports for the same data.
4. Remove the private `product_contributors` association for that UUID. Its FK currently sets the user ID to null, and public manufacturer catalog facts can remain. Remove private support feedback copies and request attachments except any narrowly necessary retention record. Review auth audit entries and operational records under the provider's supported controls; document a specific security retention exception if needed instead of promising unverified log erasure.
5. Delete the exact auth user with Supabase's supported permanent admin deletion operation. Current FK cascades remove `user_workspaces`, `scan_submissions`, the social profile and its friendships/blocks/invitations/memberships/posts/signals, owned groups, and import/social limit rows. Never run a blanket table deletion. No service-role credential belongs in the app or public website.
6. Verify the account and each related table have no remaining matching active records; check feedback JSON and non-cascading relationships separately. Check that no unrelated account was affected. For selected-data requests, remove only the verified requested records and keep authentication intact.
7. Confirm completion and its scope to the requester through the support channel. Keep only the requesting email, dates and outcome for up to 90 days, then remove that minimal record and related support correspondence unless a documented legal/security exception applies. Remove the UUID from completed support notes. Do not claim deletion is complete while identifiable active records remain.

Current Supabase Free project does not include scheduled project backups (verified in Database > Backups). If plan, backup strategy, providers, retention practices or app collection changes, revise the public privacy/deletion pages and Play Data safety before rollout. Provider operational records are governed separately; accessible log history is not proof of backend retention duration.

Moderation: Review in-app reports and support requests, remove violating posts, and restrict abusive accounts as appropriate. The public Community guidelines prohibit harassment, hate, sexual content, graphic violence, illegal transactions, privacy violations and spam. Reporting is not an emergency service.
